# レビュー指摘対応

レビュー指摘を番号付きの対応表(markdown)で管理し、セッションを跨いでも対応漏れ・二重対応を防ぐためのワークフロー。

## 対応表の作成(初回)

1. 指摘元(PRレビューコメント・レビュー結果・ユーザー提供のリスト)を読み、対応表を作成する。
   - ファイル名: `<topic>-review.md`(例: `pr554-review.md`)。既存の対応表があればそれを使い、新規作成しない。
   - 置き場所: ユーザーの指定に従う。指定がなければリポジトリルートに置き、コミット対象にしない。
2. 各項目のフォーマット:
   - 番号 / 指摘内容の要約 / 指摘箇所(`file:line`) / 状態(未対応・対応済み・対応不要) / 対応方針
3. 番号一覧をユーザーに提示し、どれから対応するか指示を待つ。勝手に対応を始めない。

## 対応(番号指定を受けて)

1. 指定された番号だけに対応する。指定外の項目・周辺コードに手を出さない。
2. 1件ずつ進める: 対応方針を短く示す → 実装 → 差分を要約 → 次の番号へ。
   複数番号が一括指定された場合も、1件ずつ区切って進め、まとめて変更しない。
3. 対応方針が指摘と食い違う場合や複数の解釈がある場合は、実装前に選択肢で確認する。
4. 指摘自体に反論がある場合は、対応せず「対応不要の提案」として理由を添えて出す。

## 対応表の更新

- 「更新して」と言われたら、実際に行った対応内容を各項目の状態・対応方針欄に反映する。
- 対応していない項目を対応済みにしない。対応不要と判断した項目は理由を書く。
- レビューへの返信コメントの投稿はしない。必要ならドラフトを作成してユーザーに渡す。
